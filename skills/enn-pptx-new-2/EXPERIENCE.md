# 优化记录

每轮优化记下依据和结论，下一轮先读这里。只记有使用证据支撑的结论；只出现过一次的现象放在"待观察"，不写成规则。

## 2026-10-27：按 8 次真实使用会话优化

**依据**：2026-09-27 至 10-26 共 8 个用 enn-pptx(现改名 enn-pptx-origin)改 PPT 的 Claude Code 会话。全部是在已有 PPT 上围绕一两页反复修改，没有一次是从模板新建整份 deck。

| 现象 | 证据 | 改动 |
|---|---|---|
| PowerPoint 提示文件损坏，`validate.py` 却显示通过 | 两次：`algn="1000"`（字号传到了对齐参数）、`wrap="None"`。第一次靠用户逐个打开 6 个排查文件才定位 | `helpers/pptx_slide.py` 把"属性值不在允许取值内 / 类型不对"加入幻灯片致命错误清单。人为写入两种非法值能报出，桌面 30 份真实 PPT 无误报 |
| 文字、图标、方块压边框，箭头只剩三角 | 2 个会话里用户指出 10 次，如「冷启动那部分的内容和边框重叠了」「有点箭头只剩一个三角了，一点都不美观」「修复agent那块压到边框了」 | 新增 `scripts/check_layout.py`。合成的四类缺陷全部报出，有意压边框的页签不报；`--original` 排除模板和原文件已有的 15 条 |
| 模型另存新文件，用户要求原地改 | 「直接在V7上改」「直接在之前的那个ppt上改就行」「把那两个另存的文件删掉」 | SKILL.md 新增"修改现有页面"流程，默认原地写回，改前备份 |
| SKILL.md 大段内容在实际使用中用不到 | 8 个会话里 PLANNING/LAYOUT/MODULES 零读取，pptxgenjs 零使用 | pptxgenjs 清单移到 `PPTXGENJS.md`（通用配色和字体列表在 2.0 重构时已删除） |
| 页面上出现"（示意）""（规划中）"、来源脚注、注释，用户逐个删除 | 3 个会话 9 次，如「把（示意）去掉」「不要在右下角标注外部技术来源」「评测基准（规划中）这个是你额外加的吗」。原因是 PLANNING.md/RESEARCH.md 要求页面保留示意标记和页脚引用 | 标记只写在规划和回复里；补充内容在回复中逐条交代 |
| 用户反复追问内容是否来自材料 | 5 个会话 8 次，如「严格贴文档」「文档里有提及这个难点吗」 | SKILL.md 新增"内容来源" |
| 表述抽象、口语、有 AI 味 | 5 个会话 14 次，如「表述别太抽象，要正式、专业、有逻辑」「不要用"变了什么"这种抽象且ai味儿很重的表述」 | SKILL.md 新增"文案"通用原则 |

**几何检查的取舍**：用 3 份真实 PPT 的渲染图核对后，排除了这些误报来源：作为箭头头部的小三角、斜面/圆柱等外接矩形和轮廓不一致的形状、骑在边框上的有底色页签、被有底色标签遮住的连线、无边框文本框的溢出。几何事实不等于缺陷，脚本只列事实，由模型对照渲染图判断。

## 2026-11-02：修改现有 PPT 时沿用文件自身的样式

**依据**：用户说明实际使用中很少用到公司模板，主要在已有 PPT 上改。SKILL.md「设计约束」的字号表（标题 36-44pt 等）继承自通用 pptx skill，改现有页面时如果照表执行，新画内容会和同一文件其他页的字号、配色不一致。

| 改动 | 说明 |
|---|---|
| 「修改现有页面」第 3 步加样式来源规则 | 字号、配色、字体、间距先从同一文件的同类元素取值，「设计约束」的数值只在找不到参照时用 |
| 「设计约束」开头注明改现有 PPT 时表内数值只作缺省值 | 与第 3 步保持一致 |
| 修正过期引用 | COMPANY_STYLE.md 指向 SKILL.md 里已不存在的 pptxgenjs 清单，改为 PPTXGENJS.md；eval 2 的"三道交付检查"改为四道 |

**暂不处理（涉及模板，用户要求先不考虑）**：公司模板实测标题约 25.5pt，与字号表 36-44pt 不符；eval 3 在"不编造""不留占位""幻灯片不写标记"三者之间缺一条规则；新建流程示例写死 `/tmp` 路径。

## 2026-11-03：按 10-29、10-30 的 5 个真实会话优化

**依据**：10-27 优化后用 `/enn-pptx-new-2` 的 5 个会话。3 个是在已有 PPT 上反复改一两页，2 个是把图片转成一页 PPT；其中 2 个会话还从几份 PPT 里挑页合成新文件。

| 现象 | 证据 | 改动 |
|---|---|---|
| 文字看不懂：为省版面把意思压成自造短语 | 10-30 一个会话里问了十几次"是什么意思"，如「这句话没人能看懂」「太晦涩了」，被追问的说法有「本体不一」「术语难同一」「多源识别」「能力成分」 | 「文案」加规则：版面放不下就缩句、删次要信息或改版面，不自造缩略说法 |
| 内部分析框架的词写到了页面上 | 「不要提及干什么、怎么干和干成的效果」同一会话说了 4 次；「不要提及槽位」「没有必要强调输出」 | 「文案」加规则：框架、维度名、字段名只用于思考；本次对话里被否掉的说法，之后每次改都要对照 |
| 难点只写了现象 | 「不要陈述现象，要点明问题的本质」「你认为这三个难点是技术难点吗」 | 「文案」加规则：问题、难点要写出原因 |
| 问题、目标、难点、方案对不上 | 「右侧技术方案能解决这个问题吗」「易出错不就是在否定我们前边的内容了吗」「是不是跟前面的限定词识别有点重复了」「这个目标看起来在说干什么，而不是一个目标」 | 新增「页内逻辑」：一一对应、互不重叠、立场一致、目标写成状态，改完从头读一遍 |
| `check_layout.py` 报 PASSED 后，用户仍指出箭头只剩三角、文字压边框 | 两次都在用户指出前报过 PASSED。用桌面成品还原当时的缺陷后复现：(1) 按 3 倍线宽估箭头头部，0.75pt 线只算 3pt，实际渲染约 0.08"；(2) 文字只查"越过"框线且有 2pt 余量，贴在线上的报不出 | 细线的箭头头部按至少 2pt 线宽估算；文字在上下方向离框线不足 1.5pt 也报（左右方向换行宽度估得太粗，不查）。两处还原的缺陷都能报出。代价是用户成品上的"估算"条目变多，抽查里有真问题（虚线框穿过文字、文字压在栏底线上），也有误报（小标签） |
| 渲染图不可信 | 本机没有微软雅黑和等线，LibreOffice 换用其他字体，会话中出现"手写体""宽体"；COMPANY_STYLE.md 却写着"不会有宽度替换问题" | 「转换成图片」先查字体，缺字体时在回复里说明并告诉用户装法（Office for Mac 自带字体文件）；修正 COMPANY_STYLE.md 的说法 |
| 跨文件抽页每次现场手拼 | 2 个会话都在现场比对版式、母版和关系文件 | 新增 `scripts/merge_slides.py`；「任务分流」加上"挑页合成"和"图片转一页"。用两组真实会话的输入和一组母版不同的模板组合测过：validate 通过，渲染与原页一致，相同母版只导入一次 |

**验证**：从这 5 个会话里取 3 个任务（跨文件合页、逻辑链改写、图片转一页，即 eval 4-6），新旧版各跑一遍。检查项通过率：新版 16/16，旧版 13/16。旧版没通过的 3 项：目标仍写成"打造……库"的动作写法；难点小字用了"充当定语"这类术语；图片任务的回复没提渲染字体缺失。耗时新版平均 148s，旧版 132s；新版多出的时间主要花在缺字体导致的反复渲染上。旧版做合页任务时同样做成了，但为此现场写了一个导入脚本。

## 2026-11-04：迁移到 Codex

**依据**：当前安装路径为 `~/.codex/skills/enn-pptx-new-2`，Claude Code 已卸载，通用 `pptx` 技能已删除；入口仍含 Claude 专用 hook 和旧安装路径。

- 移除 Claude frontmatter hook；模板保护改为任务前后显式 SHA-256 校验。此检查只检测改动，不声称阻止写入。
- 增加 Codex 工作目录、工具权限、依赖探测、图片检查和交付路径说明；保留现有模板、样式优先级与四道交付检查。
- 已有授权时继续执行；保留用户主动要求的规划确认，不把未回复当作同意，不用未验证的数字补足真实成果。
- 清理对已删除 `pptx` 技能的运行依赖，保留上游来源说明和原有技能名称。
- 验证以实际脚本和隔离工作副本为准；未执行的完整行为或视觉评估不能宣称通过。

**本轮实际验证**：技能结构校验通过；指纹脚本的未变更、修改、缺失、新增、禁止覆盖基线分支通过；从模板抽取一页的工作副本通过 validate、check_delivery（修复元数据后）及 check_layout。LibreOffice 在沙箱内异常退出，按执行工具授权在沙箱外重试后成功生成 PDF。仅覆盖工具链冒烟测试，未执行全部 7 个行为评估，也未代表复杂汇报的视觉质量验收。

## 2026-11-04：统一数据和纯文字页面规则

**依据**：用户审阅后明确同意统一两处冲突。旧条款允许缺数字时补示意值且默认不在页内标注，与真实成果不可编造的规则冲突；入口要求每页有图形，与公司版式允许纯文字要点页冲突。

- 真实成果等事实缺失时不主动填示意值；外部事实无法验证时不得用假设或示意值充当论据，外部基准也不能当成本项目实绩。
- 用户明确要求模拟／示例数据时可生成，但必须在数据所在页保留可见标识。此条优先于历史记录中“标记只放回复”的默认约定。
- 允许清晰的纯文字结论、决策和说明页；保留内容密度与留白检查，不强制添加图标、卡片或装饰。
- 更新缺数据场景，补充模拟标识、纯文字决策页和无来源收益主张的回归场景；这些是待执行的行为验收定义，不代表已通过完整行为评估。
